# TinyLogLibrary 架构指导

## 核心理念

> Logger 管判断和分发，Recorder 表示一条日志，Sink 管写到哪里，Stylizer 管输出格式。

每个 phase 都是**可编译、可运行的**，不追求一步到位。

---

## Phase 1：最小可用原型

**目标**：一条日志能从业务代码写到控制台。

### 产出文件

```
tiny_log/
  LogLevel.h        ← 日志等级枚举
  SourceLocation.h  ← 源码位置结构体
  LogRecord.h       ← 一条日志的数据包
  Sink.h            ← Sink 抽象接口
  ConsoleSink.h     ← 控制台输出
  Logger.h          ← 核心日志器
  Logger.cpp
  Logging.h         ← 入口宏 + 函数
```

### 需要解决的问题

| # | 问题 | 方案 |
|---|------|------|
| 1 | 日志等级 | `enum class LogLevel { Debug, Info, Warn, Error, Critical }` |
| 2 | 日志内容 | `LogRecord` 包含 level、message、time、source_location |
| 3 | 输出到哪 | `ISink` 抽象接口，第一版只有一个 `ConsoleSink` |
| 4 | 等级过滤 | `Logger::ShouldLog(level)` 比较后决定是否输出 |
| 5 | 源码位置 | 宏 `LOG_INFO(msg)` 捕获 `__FILE__`/`__LINE__`/`__func__` |
| 6 | 入口函数 | `Logging.h` 提供 `LOG_DEBUG/INFO/WARN/ERROR/CRITICAL` 宏 |

### 不做的

- 没有文件输出
- 没有格式化器（直接拼字符串）
- 没有多线程支持
- 没有多 Logger / Registry
- 没有 fmt 依赖（纯 `std::string`）

### 类关系

```
LOG_INFO("hello")
    │
    v
Logging.h 宏   ← 捕获 __FILE__, __LINE__, __func__
    │
    v
Logger::Log(LogLevel, string, SourceLocation)
    │
    ├── ShouldLog(level)  → 等级不够就丢弃
    │
    v
LogRecord  ← 把 level + msg + time + location 打包
    │
    v
遍历 sinks
    │
    v
ConsoleSink::Write(record)  → std::cout
```

### 预期输出

```
[2026-05-15 14:30:00] [Info] [main.cpp:12 main] hello world
```

## Phase 2：格式化和文件输出

**目标**：日志可以写到文件，格式可以自定义。

### 新增/修改文件

```
tiny_log/
  Formatter.h       ← NEW：格式器抽象
  DefaultFormatter.h← NEW：默认格式实现
  FileSink.h        ← NEW：文件输出
  (ConsoleSink 改用 Formatter)
```

### 需要解决的问题

| # | 问题 | 方案 |
|---|------|------|
| 1 | 格式写死在 Sink 里 | 抽出一个 `Formatter`，Sink 持有它 |
| 2 | 输出到文件 | `FileSink` 打开文件、写入、关闭 |
| 3 | 控制台和文件格式不同 | 每个 Sink 可以有不同的 Formatter |

### Formatter 接口

```cpp
class IFormatter {
public:
    virtual ~IFormatter() = default;
    virtual std::string Format(const LogRecord& record) = 0;
};
```

### 预期效果

```
// 控制台（带颜色/简洁）
[Info] hello world

// 文件（带时间戳/完整信息）
[2026-05-15 14:30:00.123] [main.cpp:12 main] [Info] hello world
```

## Phase 3：滚动日志和多线程安全

**目标**：生产环境基本可用——文件不会无限膨胀，多线程不乱。

### 新增/修改文件

```
tiny_log/
  RotatingFileSink.h   ← NEW：按大小滚动的文件输出
  detail/
    NullMutex.h         ← NEW：空锁（单线程场景零开销）
```

### 需要解决的问题

| # | 问题 | 方案 |
|---|------|------|
| 1 | 日志文件太大 | `RotatingFileSink` 按大小切分，保留最近 N 个 |
| 2 | 多线程写同一 Sink | Sink 内部加 `std::mutex` |
| 3 | 单线程不要有锁开销 | 模板 Mutex 参数，单线程传 `NullMutex` |

### 旋转策略

```
app.log      → app.1.log
app.1.log    → app.2.log
app.2.log    → app.3.log
超过保留数则删除最旧文件
```

### 线程安全设计

```cpp
template<typename Mutex = std::mutex>
class RotatingFileSink : public ISink {
    Mutex m_mutex;  // 单线程传 NullMutex，零开销
};
```

## Phase 4：多 Logger 和全局管理

**目标**：不同模块有独立的 Logger，互不干扰。

### 新增/修改文件

```
tiny_log/
  Registry.h          ← NEW：全局 Logger 注册表
  Registry.cpp
```

### 需要解决的问题

| # | 问题 | 方案 |
|---|------|------|
| 1 | 所有模块共用一个 Logger | Registry 管理多个命名 Logger |
| 2 | 模块需要独立控制等级 | 每个 Logger 有自己的 level |
| 3 | 模块默认用同一个 | 提供 DefaultLogger，按需创建命名 Logger |

### 使用方式

```cpp
// 默认日志器（大多数情况）
LOG_INFO("程序启动");

// 模块专属日志器
auto* renderLogger = logging::Registry::Get("Render");
renderLogger->SetLevel(LogLevel::Debug);
LOG_INFO_TO(renderLogger, "渲染初始化");
```

### 结构

```
Registry
  ├── default Logger  ← 全局默认，LOG_INFO 默认走这个
  ├── "Render" Logger ← 渲染模块
  ├── "Network" Logger← 网络模块
  └── ...
```

## Phase 5：异步日志

**目标**：日志写入不阻塞业务线程。

### 新增/修改文件

```
tiny_log/
  AsyncSink.h         ← NEW：异步 Sink 包装器
  detail/
    RingBuffer.h      ← NEW：无锁环形队列
    ThreadPool.h      ← NEW：后台写线程
```

### 核心思路

不是在 Logger 层做异步，而是在 Sink 层：

```cpp
// AsyncSink 包装一个真实 Sink
// 业务线程把 LogRecord 丢进队列立刻返回
// 后台线程从队列取出，交给真实 Sink 写入
class AsyncSink : public ISink {
    RingBuffer<LogRecord> m_queue;
    std::thread m_worker;
    std::unique_ptr<ISink> m_realSink;  // 可以是 FileSink / ConsoleSink
};
```

```
业务线程                       后台线程
    │                              │
    │ Push(record) ──→ 队列 ──→  Pop(record)
    │ 立刻返回                      │
    │                              │ m_realSink->Write(record)
    │                              │
```

### 不做的

- 无锁队列的高性能优化（留给进阶）
- 异步模式下的 crash 兜底

## Phase 6：高级特性（可选）

这些看需要再加，不一定要做：

- **ColorSink** — 控制台彩色输出（按等级着色）
- **CallbackSink** — 把日志回调给用户自定义函数
- **fmt 支持** — `LOG_INFO("x={}", x)` 模板格式化
- **流式入口** — `LOG_INFO_STREAM << "x=" << x`
- **条件日志** — `LOG_INFO_IF(cond, msg)` 满足条件才输出
- **PeriodicWorker** — 定时 Flush
- **环境变量控制** — `TINY_LOG_LEVEL=Debug` 启动时设置等级

## 迭代顺序总览

```
Phase 1 ──→ Phase 2 ──→ Phase 3 ──→ Phase 4 ──→ Phase 5
  │            │            │            │            │
  │            │            │            │            └── 异步（进阶）
  │            │            │            └── 多 Logger（管理）
  │            │            └── 滚动 + 线程安全（生产可用）
  │            └── 格式化 + 文件输出（功能完善）
  └── 最小原型（理解核心流程）
```

**核心原则**：每个 phase 都是可编译可运行的，不要跳步。
